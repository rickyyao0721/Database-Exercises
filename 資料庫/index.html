電影院訂票管理系統

從電影、場次、座位到會員訂票，建立一套可查詢、可統計的示範資料庫。你可以編輯 SQL、實際執行，並比較不同條件造成的結果差異。

01｜案例背景

資料庫給誰使用？

本系統提供電影院管理員、售票人員與會員使用。管理員負責管理電影與放映場次；售票人員需要確認座位狀態、查詢訂單；會員則需要查詢場次與自己的訂票紀錄。

要解決什麼問題？

  • 快速查詢電影與放映時間。
  • 確認某場次哪些座位已被訂走。
  • 查詢會員訂票紀錄及訂單狀態。
  • 統計電影票房，協助安排熱門場次。
系統規則：每筆 Bookings 訂票紀錄代表一位會員在某場次購買一個座位。狀態分為 paid（已付款）、pending（待付款）、cancelled（已取消）。本範例把 paid 與 pending 視為暫時占用座位，cancelled 不占位。

05｜結果比較：修改 SQL 會發生什麼事？

以「統計電影票房」為例，觀察是否加入訂票狀態條件會如何影響統計結果。

版本 A｜只統計已付款

較接近實際票房

WHERE Bookings.status = 'paid'

只計算已付款的訂票紀錄。待付款與已取消訂票不會被算入收入。

預期合計：1,230 元

版本 B｜不限制狀態

所有訂票都計算

-- 移除 WHERE 狀態條件

會把 pending 與 cancelled 也加進去。雖然總額增加，但不能代表已收取的票房。

預期合計：2,110 元

為什麼不同？樣本資料中 pending 有 300 元，cancelled 有 280 元。移除 paid 條件後，總額會多算 580 元。這說明 SQL 查詢必須依照題目定義決定篩選條件，而不是只看查詢能不能執行。

可自行驗證的 SQL

將以下兩種版本分別貼到上方編輯器執行，對照結果。

版本 A
SELECT Movies.title, SUM(Bookings.price) AS revenue
FROM Bookings
JOIN Showtimes ON Bookings.showtime_id = Showtimes.showtime_id
JOIN Movies ON Showtimes.movie_id = Movies.movie_id
WHERE Bookings.status = 'paid'
GROUP BY Movies.movie_id, Movies.title;
版本 B
SELECT Movies.title, SUM(Bookings.price) AS total
FROM Bookings
JOIN Showtimes ON Bookings.showtime_id = Showtimes.showtime_id
JOIN Movies ON Showtimes.movie_id = Movies.movie_id
GROUP BY Movies.movie_id, Movies.title;
